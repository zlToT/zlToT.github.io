请帮我开发一个「纯前端单页图片压缩工具」，参考 TinyPNG 的交互体验，整体要求如下：

【一、核心定位】
- 单页应用，纯浏览器端运行，不依赖任何后端 / 服务器 / API Key，图片不上传，保护隐私。
- 免费无次数限制，无单文件大小限制（仅受浏览器内存约束，建议在 UI 中提示"单张 > 50MB 可能变慢"）。
- 移动端 + 桌面端响应式，现代浏览器（Chrome / Edge / Safari / Firefox）均可用。

【二、功能需求】
1. 多格式支持：JPG / JPEG / PNG / WebP / GIF（静态帧）/ BMP / AVIF 输入。
2. 批量处理：支持文件选择器 + 拖拽上传 + 粘贴（Ctrl/Cmd+V），单次最多 50 张。
3. 压缩精度可选，提供三档预设 + 自定义滑块（0-100）：
   - 轻度（quality 0.85）：几乎无损，适合摄影作品
   - 推荐（quality 0.70）：体积与画质平衡，默认选中
   - 极限（quality 0.45）：体积最小，适合社交分享
4. 输出格式可选：保持原格式 / 统一转为 WebP / 统一转为 JPEG。
5. 可选功能（折叠在"高级选项"中）：
   - 最大边长限制（如 1920 / 1280 / 自定义）
   - 是否去除 EXIF 元数据（默认开启）
   - 压缩后仍大于原文件时是否回退为原文件（默认开启）

【三、压缩实现逻辑（关键）】
- 默认引入 browser-image-compression 库（npm i browser-image-compression），用 Web Worker 处理避免阻塞主线程。
- 同时引入 canvas + toBlob 作为降级方案，通过 File API + createImageBitmap 解码，Canvas 重绘，toBlob('image/jpeg'|'image/webp', quality) 重新编码。
- PNG 特殊处理：因为 Canvas 对 PNG 强制有损编码效果差，对 PNG 输入需用 @jsquash/png 或 upng-js 做 K-d 树调色板量化（256→128→64→32 色），实现类 TinyPNG 的有损压缩。
- WebP / AVIF 通过浏览器原生 toBlob 支持，Safari 不支持时降级为 JPEG 并提示。
- 多工具并行压缩 + 取最小体积（参考 compressWithMultipleTools 模式）。

【四、UI / UX 设计】
- 首屏：醒目的虚线拖拽区 + 按钮双入口，文案"拖入图片，或点击选择"，下方小字"所有处理都在你的浏览器完成，图片不会上传到任何服务器"。
- 文件列表卡片，每张显示：缩略图、文件名、原大小 → 压缩后大小、节省百分比（绿色徽章，如 -78%）、单张下载按钮、删除按钮。
- 列表顶部显示统计栏：共 N 张 / 原始总大小 / 压缩后总大小 / 共节省 X MB。
- 压缩中显示进度条，逐张实时更新，不阻塞交互。
- 底部提供"下载全部"按钮，用 fflate 或 JSZip 打包 ZIP。
- 配色参考 TinyPNG：浅灰背景 + 青蓝色主色调（#2ECCB0 类似），圆角卡片，简洁现代。
- 空状态、加载中、压缩失败三种状态都要有清晰提示。

【五、技术栈与交付】
- 技术栈：Vite + 原生 TypeScript（或 Vue 3 / React 任选其一，说明理由）。
- 代码结构：src/index.html、src/main.ts、src/compress.ts（压缩核心逻辑单独抽出）、src/style.css。
- 全部代码放在一个回复中输出，包含可直接 npm run dev 运行的完整项目，关键函数加中文注释说明压缩流程。
- 无构建也可运行：额外提供一份纯 HTML + CDN 引入的 index.html 单文件版本。

【六、验收标准】
- 拖入 5 张 5MB 的 JPG，能在 10 秒内完成压缩并正确显示节省比例。
- PNG 带透明通道的图片压缩后透明背景保留不变成黑色。
- 关闭网络后所有功能仍然可用。
